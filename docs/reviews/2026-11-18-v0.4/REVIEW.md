# CoCraft 0.4.0 桌面版产品实测评审

2026 年 11 月 18 日，macOS arm64。实机走查、解码与记录共约 33 分钟。评审对象为仓库交付的 `release/0.4/mac-arm64/CoCraft.app`，应用报告版本为 0.4.0。

**当前版本可用于短片原型和受控演示。用于客户交付、口播精剪或多人接力之前，建议先修下面十项。** 创作者目前还得自己核对锁定镜头的内容、轨道静音的范围、字幕的时间点，以及分镜卡到底代表哪一帧。成片已经成功导出，仍然会出现这些错误。

## 十项应当优先修复的问题

| # | 实际操作与结果 | 对创作者的影响 | 建议及复验条件 |
|---|---|---|---|
| **1** | **锁定镜头可以被重连成另一段内容。** 锁定蓝色的两秒片段，移走测试源文件。离线预检正确报警。在属性里把它重连到时长、尺寸相同的纯绿色 MP4，应用直接接受，片段仍显示锁定。再次导出，0.25 秒处由蓝变绿。 | 客户确认过的镜头可以在继续显示锁标记的情况下被改掉。同源的其他片段也受影响。 | 区分找回同一文件和替换素材。相同内容换路径应直接恢复。不同内容应列出受影响镜头，对已锁定引用保留原版本或明确要求解锁。复验应比较实际输出帧。 |
| **2** | **静音背景音乐会连同期声一起关掉。** 主镜放入带 660 Hz 测试声的四秒 MP4，独立声音轨放十秒底乐，仅点「静音声音轨」。源视频有 AAC，导出的 MP4 只有 H.264，连音频流都消失了。 | 只是想暂时关音乐听清人声，交付出来可能整片无声。 | 分开视频内嵌音频、独立声音轨和监听总静音。三路分别开关，逐一检查导出音轨，不能只检查按钮状态。 |
| **3** | **从文稿拆镜会静默删掉开头的数字。** 四行输入 `2026 年首次亮相`、`3.5 倍光学变焦`、`35mm 镜头拍摄`、`100% 回收材料`，生成后标题和字幕分别成了「年首次亮相」「倍光学变焦」「mm 镜头拍摄」「% 回收材料」。 | 产品参数、年份和比例在创作起点就丢失。用户后续校对的是已经改坏的文本。 | 默认逐字保留。只有明确的列表标记才允许剥离，并为数字、负数、型号和中文编号建立往返用例。 |
| **4** | **在分镜里改一个标点，会抹掉逐句字幕的时序。** 红镜有两条 SRT，镜内帧区间分别为 0–24、27–54。分镜将两句显示在同一框。在句末加一个句号，结果变成一条覆盖整个 60 帧镜头的字幕。撤销可恢复两条。 | 已校准的停顿、切句和阅读节奏被重写。简单文字校对的代价过高。 | 分开本镜旁白草稿和已对时的字幕。支持逐句改字并保留时间。整镜重排字幕应单独触发，并预告将合并几句。 |
| **5** | **分镜换序后，贴着画面的提示音留在旧位置。** 将红、蓝两镜对调，三条字幕跟着正确移动。与红镜同时开始的独立提示音仍留在第 0 帧。导出后 0.25 秒蓝画面有提示音，2.25 秒红画面已静音。 | 产品操作音、口播配音和画面会失去同步。长背景音乐确实又经常需要固定在时间线上。 | 提供「随镜」「固定在时间线」两种归属，支持查看、绑定和解绑。换序时只移动随镜声音，复验同时放入一个音效和一条跨镜底乐。 |
| **6** | **「沉淀当前镜」复用出来的是另一段剪辑。** 选中四秒源片的蓝色后半段，原素材入点 60 帧、时长 60 帧。沉淀后把该资产拖回时间线，新片段入点 0、时长 120 帧，从红色开头重新播放。镜头的字幕没有一起带回，资产还被标成「数据与逻辑图解」。 | 团队以为收藏了已经剪好的两秒片段，实际拿到整段原片。 | 把镜头区间、源入出点、图层、字幕、绑定和依赖版本存为可复用镜头。提供「只收录源素材」独立入口。重新插入后应能逐帧对比原镜。 |
| **7** | **从空工程开始，舞台手柄和打点会失效。** 空工程导入并入轨，暂停、在时间线选中可见镜头。舞台有画面，操控层已有 814×456 的可见面积，却没有生成内部视口或手柄。点击舞台中心也没有坐标引用。退出并重开同一工程，内部视口和手柄出现。 | 首次上手的用户恰好遇到最差路径，容易误以为只能在右栏输坐标。 | 在舞台从空变为有内容、播放回到暂停、容器重新挂载时重新测量。以冷启动空工程为入口，直接拖动、缩放、打点并验证项目坐标。 |
| **8** | **分镜缩略图不能用来审镜头。** 同一源片切成红、蓝两段。停在第二镜时，播放器是蓝色，两张分镜卡却都是红色，第二张甚至叠着正确的「蓝色整句」字幕。两卡实际取的是同一个素材缩略图。 | 靠卡片选镜、排镜、比候选时，会对画面作出相反判断。 | 按片段源入点、当前候选和合成快照抽帧，缓存真实代表帧。先保证任一静止状态下卡片、播放器和导出的同一帧一致。 |
| **9** | **「为镜头生产 AI 候选」没有把结果挂回这个镜头。** 先留两个候选，再从这张卡生成图像。本地协议服务成功返回实图，后台显示完成，候选仍为两个。点唯一的「添加到时间线」，片段从 2 个变成 3 个，候选仍为两个。普通模板候选能正常进入候选列表。 | 每次生图后都要重新找到目标镜头。点系统给出的继续按钮还会新增一层，改变原有剪辑。 | 作业保存工程、分支、镜头和目标行为。成功后追加未激活候选，给出并排比较与采用入口。目标已删除、锁定或切换分支时保留结果并提示重新指定。 |
| **10** | **导出预检漏掉了整整六秒的空片尾。** 四秒视频加十秒底乐，预检显示「未发现空洞或溢出风险」。导出确为十秒，第八秒只有工程背景色。同一版能发现时间线中段的 0.66 秒空隙。 | 短视频会带着很长的空尾交付，预检的肯定性文案还会降低人工复核意愿。 | 对完整导出区间求视觉覆盖，检查片头、中段、片尾和全片无视觉的情况。创作者可确认有意留白。检查服务异常应显示「未完成检查」，当前界面会把异常转成空问题列表。最后一句来自代码核查。 |

## 已经做对、值得保留的部分

- **经典剪辑操作有一条可靠主线。** 通过桌面入口导入文件、素材入轨、按播放头分割、SRT 导入、逐帧对应字幕、版本恢复都可以工作。实际按 ⌘Z 和 ⇧⌘Z，单次添加可往返恢复。跨镜移动时，已有的字幕跟随行为应保留。
- **本地工程确实独立于聊天。** 关掉应用再打开，原工程 ID、版本、片段结构和锁定状态保留。创建 9:16 副本得到了独立的 1080×1920 时间线，主片保持 1920×1080。中途取消的竖屏导出作业进入已取消状态。
- **编码 Agent 和源码素材包有产品价值。** 载入随附包后可以编辑真实 TSX。我故意提交不完整的组件，在错误面板看到了编译位置，工程保持 v36。Pi 回归中，文件读写、编译、发布和静默验画均通过。继续保留源码入口、可撤销发布和 Skill 扩展能力。
- **有些失败和返回路径处理得很好。** 缺源文件时预检能逐片段列出问题。素材工作室去配置模型再返回，已经输入的画面描述仍在。本机中文配音实际完成并入库。依赖真实在线服务的结果需要单独验收。

## 验证依据与边界

- 以独立临时数据目录启动打包版，用 Playwright 操作实际 Electron 窗口。覆盖空白和已有工程、深浅主题、画布与资产树、分镜候选、时间线、文稿、属性、命令面板、版本、项目与全局风格、素材工作室、后台作业、源码包、导出与重开。桌面文件选择测试固定返回自制样本路径，后续导入走应用本身。读取项目快照核对时间、引用和版本。最小窗口和常规窗口分别为 1080×720 与 1440×900。
- **交付包既有五项验收本次全部通过。** 覆盖主体引用和生成上下文、画面与字幕换序、已有 Agent 会话分支隔离及历史派生，以及真实 H.264/AAC MP4 导出。该 MP4 时长 5.01 秒，523,596 字节。Agent 分支测试使用本地模型协议夹具。既有用例建立主体连线采用下拉绑定，将 MP4 拆成两段时直接构造了编辑操作。本文另从实际时间线分割按钮与 SRT 导入入口做了交叉验证。
- **另外三条交付文件经过独立解码。** 换序成片为 1920×1080、30 fps、4.011 秒，H.264/AAC。0.25 秒左上角像素 RGB 为 (0,1,252)，有提示音，2.25 秒为 (252,0,0)，该采样窗静音。重连后的成片在 0.25 秒变为 (1,127,1)。静音案例的十秒输出只有视频流，第八秒为工程背景色。编码容器成功和内容正确分别核对。
- 当前源码的 `npm run test:unit`、`npm run smoke`、`npm run smoke:agent` 和 `npm run smoke:models` 均通过。本轮的生成候选另用本机协议服务返回真实图片文件，单独检查它是否归入发起镜头。云端模型质量、在线 Pexels 账号、外部商业素材包兼容性，以及长片 4K／HDR 播放性能均未在本轮验证。32 卡检查测的是导航和适配，不能据此推断长片性能。
- 以上 25 项以打包版实操为主，工程入口和预检异常分支另有源码核查。视觉、布局及优先级属于评审判断。本轮产物为评审与复现材料，产品功能等待后续修复。

**下一项最小交付建议。** 用同一条四秒双色素材建立一条固定回归。锁定蓝镜，先移走原文件并按相同内容重连，再尝试换入绿片。让红镜带一条短音效、两句字幕，另放跨镜底乐。换序、修标点、静音底乐，再导出。交付条件为锁定蓝镜仍是蓝色、同期声仍在、音效跟红镜、两句字幕保留断点、两张分镜卡与实际成片一致。这个用例通过后，再扩展生产器和预设目录。
