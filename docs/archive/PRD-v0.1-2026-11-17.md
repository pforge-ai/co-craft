# CoCraft Mac 视频剪辑 PRD 草案

版本：v0.1　日期：2026 年 11 月 17 日　状态：产品对齐草案

CoCraft 是暂定项目名。产品是一款由 Agent 持续执行剪辑、创作者随时预览和接管的 Mac 视频工作台。口播访谈、AI 短片组装、成片修改与多平台版本共用一份可编辑工程，通过文稿、分镜、时间线三种视图组织工作。

第一阶段服务发起人的真实项目，并逐步向个人创作者开放；工程能力以专业剪辑师和工作室为长期目标。本版用于确定产品范围、交互规则和验收方式，具体实现方案另行形成技术设计。

## 产品方向与决策状态

### 已确认方向

| 项目 | 已确认内容 |
| --- | --- |
| 平台 | 设计并实现 Mac app |
| 核心方式 | Agent 持续剪辑，用户随时预览、打断和局部修改 |
| 场景范围 | 同时研究口播访谈、AI 短片组装、成片修改，优先寻找共同设计 |
| 初期用户 | 先用于发起人的真实项目，同时面向个人创作者产品化 |
| 长期目标 | 按专业剪辑师和工作室的使用深度设计底座 |
| 参考对象 | ChatCut、CapCut、Premiere，以及 DeepSeek Harness、Pi Agent |

### 本版建议

以下为待评审的首版方案：三类场景各跑通一个完整流程；采用本地工程和本地预览导出；文稿、分镜、时间线共享工程；Alpha 允许自带模型 API Key；优先支持 Apple Silicon、中文内容和基础 1080p 制作。三类场景同时纳入设计，并不意味着首版承担每类场景的全部专业功能。

Pi 与 DeepSeek Harness 均为候选。Agent 底座、最低系统版本、模型供应商、收费方式和正式名称尚未锁定。

## 用户与核心问题

| 用户 | 当前问题 | 产品应交付的价值 |
| --- | --- | --- |
| 有明确内容想法的个人创作者 | 花大量时间找素材、剪停顿、对字幕、做不同画幅 | 用自然语言完成重复工作，保留细节控制 |
| 使用 AI 素材的创作者 | 剧本、镜头、候选素材与剪辑版本散落在不同工具中 | 看清每个镜头的用途、来源、候选与最终采用版本 |
| 专业剪辑师和小工作室 | 修改意见反复，自动化结果难接管，工程交接容易丢失信息 | 修改可追溯、可撤销，素材可重连，输出稳定 |

用户需要同时解决内容判断与工程执行。例如“这里太拖沓”需要判断表达与节奏；“把这段缩短两秒”需要精确执行。产品必须支持两类指令，并让用户能检查结果。

首版不要求用户理解模型工具调用、渲染命令或工程文件结构。主界面展示正在处理的内容、结果、进度、费用和需要用户判断的问题。

## 产品目标与边界

### 首版目标

1. 从本地素材出发，完成分析、初剪、人工修改、Agent 继续修改、预览和导出。
2. 三类场景使用同一工程，允许访谈、生成镜头、图片、配音和字幕混合制作。
3. 用户能够在任何阶段接管，锁定必须保留的内容，回退不满意的修改。
4. 保证工程可恢复、素材来源可追踪，预览与导出符合相同的编辑结果。
5. 用真实项目验证节奏、字幕、配音与画面连续性，形成可重复的质量检查。

### 首版范围之外

首版暂不承诺完整专业调色、复杂三维或节点合成、自动多机位剪辑、多人实时协作、移动端、Windows、自动发布到社交平台、任意 PR 或剪映工程的无损往返，以及从长剧本自动生成整部角色一致的短剧。

只有成片 MP4 时，可剪切、重排、裁画幅、追加字幕与包装；已烧录的字幕、背景音乐和特效不具备原始图层。用户界面应在相关操作时说明可编辑范围。

专业化方向体现为时间精度、工程稳定性、编辑可追溯和扩展空间；高级工具按真实需求逐步加入。

## 三类核心使用流程

### 口播访谈与播客

用户导入一段约 30 分钟的访谈，要求“围绕产品体验剪成两分钟，保留结论，删掉重复表达”。

系统建立带时间位置的转录与素材索引；Agent 组织内容，生成初剪、字幕和必要的补充画面位置。用户在文稿中恢复一句话，再锁定结尾。Agent 根据新的工程缩短中段，输出可编辑版本与成片。

验收重点：保留原意、不拼接出相反结论、切口不截断音节、字幕跟随重排、锁定结尾不变。初剪时长默认允许目标的正负 5%；用户明确要求精确时长时以项目帧为单位执行，无法兼顾约束时明确提示。

### AI 短片与短剧组装

用户导入剧本、配音和一组已生成的镜头，要求“按三场戏组装一分钟短片，先压住悬念，最后揭示”。

系统把场景与镜头卡关联到素材，保留候选片段。Agent 按剧情安排镜头、声音和字幕；缺少画面的位置标记为待补。用户替换一个镜头并调整其时长，Agent 继续修改时保留这次人工选择。

验收重点：剧本与镜头关系清楚、候选可切换、旁白与画面同步、缺失素材明确可见。首版完整覆盖已有 AI 素材的组装，模型生成和重试管理在后续阶段扩展。

### 成片修改与多平台版本

用户打开已有工程，要求“第三段缩短，字幕换成品牌样式，再做一个竖屏版本”。

Agent 在指定范围内修改，并创建独立竖屏版本。用户逐镜检查构图，修正字幕位置。横屏版本保持原样，两版可独立预览与导出。

导入外部成片时，以可追溯的源片段开展再剪辑；不能把分析出的镜头切分误称为恢复了原剪辑工程。

## 统一工程与三种视图

### 用户可理解的工程对象

| 对象 | 含义 | 必须保留的信息 |
| --- | --- | --- |
| 素材 | 原视频、音频、图片及生成内容 | 来源、时长、格式、代理文件和关联分析 |
| 内容段落 | 一段表达、剧情单元或章节 | 台词、目标、对应源素材与采用范围 |
| 场景与镜头 | 分镜卡及候选素材 | 剧情用途、人物说明、候选、已选镜头 |
| 时间线 | 可播放的剪辑结果 | 轨道、源入出点、位置、字幕、画面与音频参数 |
| 版本 | 某一时刻保存的剪辑状态 | 父版本、修改摘要、创建者、画幅与时长 |
| 任务 | Agent 工作、分析、生成或导出 | 状态、输入工程版本、产物、错误、费用 |

### 视图联动规则

文稿视图用于审阅台词和调整表达顺序；分镜视图用于安排剧情和替换候选；时间线用于精确调整时长、轨道和参数。三种视图反映同一工程状态，切换不会生成互不相关的副本。

在任一视图选中内容，其他视图能定位到对应位置。删除或重排台词会更新对应影音片段、字幕和下游时间；没有台词的镜头仍可通过分镜与时间线编辑。

“修正识别文字”“修改显示字幕”“删除对应影音”是不同操作，必须在界面中清楚区分。修正文稿错字不会自动合成新语音。纯对白素材可由内容段落自动形成初始镜头卡，用户无需补填完整剧本。

## 主工作台与基本交互

### 信息布局

| 区域 | 主要内容 |
| --- | --- |
| 顶部工程栏 | 工程名、当前版本、保存状态、撤销重做、导出 |
| 左侧素材与结构 | 素材库、搜索、内容段落、分镜列表 |
| 中央预览 | 当前画面、播放控制、时间位置、选中对象的直接操作 |
| 下方编辑区 | 文稿、分镜、时间线切换；支持收起和放大 |
| 右侧 Agent 面板 | 当前目标、阶段进度、修改摘要、费用、输入框 |
| 按需属性面板 | 选中对象的时长、构图、音量、字幕与锁定设置 |

布局应可调整，并提供“审片”和“精调”两种空间分配。聊天记录不能挤占主要预览区域。首版先验证信息结构，视觉样式另行设计。

### 选择与指令

选择镜头、文字或时间范围后，输入框显示明确的引用，例如“当前版本的第三段，00:24 至 00:38”。“只改这里”形成任务范围约束；任务执行中时间发生位移时，引用继续跟随同一内容对象。

没有选择时，指令默认作用于当前版本。“这段”“刚才那个镜头”等引用存在多种解释时，Agent 高亮候选并用一次简短提问澄清。可以通过点击候选直接回答。

### 开始与继续

第一次使用可以先导入素材并手动剪辑；启用 Agent 时再配置模型连接。系统展示当前可用能力，缺少连接时允许继续浏览、手动修改和本地导出。重新打开工程后，恢复到上次版本和播放位置，并显示可恢复的后台任务。

## 人与 Agent 共同编辑

### 持续工作规则

用户给出目标后，Agent 用简短的当前计划开始执行；普通可撤销修改默认直接落到工作版本。过程按可理解的任务阶段更新，例如“整理访谈重点”“收紧中段”“检查字幕”。

Agent 的独立分析可以后台进行；对同一工程的写入必须按确定顺序提交。每次提交是可验证、可撤销的完整编辑组。尚未完成的半组修改不应出现在可播放版本中。

用户正在播放时，当前播放使用固定工程快照；Agent 新结果显示为待预览。暂停、切换或主动查看后进入新结果，避免播放途中画面和时长突然变化。

### 追加意见与中断

| 用户动作 | 系统行为 |
| --- | --- |
| 追加“开头保持现在这样” | 更新约束，在下一次修改提交前生效 |
| 点击停止 Agent | 立即显示停止中，阻止后续修改提交，保留已完成成果 |
| 手动调整正在被处理的镜头 | 标记该范围已变化，Agent 校验后重新计算相关修改 |
| 修改无关的字幕颜色 | 保留人工修改，允许不冲突的工作继续 |
| 中断模型生成 | 尽力取消；供应商不支持取消时明确费用与任务状态，完成素材先进入素材库 |
| 恢复任务 | 从可确认的检查点继续，重新读取工程与约束 |

停止 Agent、取消导出和撤销修改是独立操作。停止本身不会自动回滚已经提交的剪辑。

### 保护人工意图

用户直接修改的对象，Agent 在当前任务内不得用旧方案覆盖；后续确有必要修改时，应指出影响并征求具体选择。用户可显式锁定整个对象或指定属性：选用素材、台词保留、时长、位置、音量、字幕样式。

“保留这句”允许整段随前文剪辑移动，但不能删除或改写其内容。“固定在 00:30”是时间位置锁定，若与缩短总时长冲突，Agent 必须先说明冲突。

写入基于旧版本、违反锁定、超出选定范围或造成不合法时间范围时，应拒绝该编辑组并重新计算。无法同时满足用户约束时，保留当前工程并提出具体取舍。

### 撤销与恢复

普通撤销按最近一次编辑组回退。对更早的某次 Agent 修改，可在没有依赖冲突时单独回退；若后续人工编辑依赖该结果，应显示受影响内容，并提供“在新版本中恢复”或连同依赖一起撤销。不能为了回退 Agent 结果而静默丢弃后续人工修改。

## 功能需求与优先级

P0 是三类流程可用的 Alpha 必备能力；P1 是公开测试及后续增强；P2 是长期专业化方向。公开测试还必须满足稳定性、安装更新和恢复门槛。

### 工程与素材

| 编号 | 级别 | 需求与验收 |
| --- | --- | --- |
| R01 | P0 | 创建、保存、打开本地工程；重新打开后，已保存版本、素材关联与编辑状态一致 |
| R02 | P0 | 拖入文件或文件夹、批量导入与重复提示；原素材不被修改，导入失败定位到单个文件 |
| R03 | P0 | 缩略图、波形、代理与分析进度；支持取消，失败项可单独重试 |
| R04 | P0 | 中文转录、时间定位与文本搜索；用户可校正识别错误，校正后不改变原声 |
| R05 | P0 | 文本、素材名、镜头标签及视觉描述检索；结果带来源和时间范围，可直接播放核对 |
| R06 | P0 | 素材离线提示与重连；缺失时保留工程结构，不能用黑画面静默替代后直接导出 |

分析结果按素材缓存。剪辑顺序改变时应复用源素材分析；替换源文件后需要重新验证。只有部分分析完成时，可以先剪辑已完成部分。

### 编辑与内容组织

| 编号 | 级别 | 需求与验收 |
| --- | --- | --- |
| R07 | P0 | 多轨分割、裁切、移动、复制、删除、波纹删除、吸附、静音和锁定；影音关联移动后保持同步 |
| R08 | P0 | 文稿、分镜、时间线选择联动；重排后能回溯到原素材位置，字幕及时更新 |
| R09 | P0 | 按主题、时长和必须保留项形成初剪；清理重复、停顿和口头语可配置，不能无差别删除全部停顿 |
| R10 | P0 | 剧本段落和镜头卡编辑、候选替换、缺失画面占位；未填充占位在导出前明确提醒 |
| R11 | P0 | 导入生成素材并保留候选、角色说明和来源；替换候选后更新受影响区间 |
| R12 | P0 | 单个对象的缩放、位置、裁切、透明度，基础淡入淡出；预览与导出参数一致 |
| R13 | P0 | 生成及校正字幕、常用样式、位置和安全区、SRT 导入导出；字幕与文稿修正可分别操作 |
| R14 | P0 | 原声、配音文件、音乐混合，音量和淡入淡出；削波风险可提示，录制或合成配音另行扩展 |
| R15 | P0 | 横竖屏独立版本，基础主体构图建议和逐镜手动调整；新版本修改不影响原版 |
| R16 | P1 | 关键帧、更多包装模板、旁白合成、音乐自动压低、降噪与更丰富的转场 |
| R17 | P1 | 内置生成供应商连接、异步生成、镜头级重试与预算；任务完成后作为候选素材可继续编辑 |

默认不因“做得更精彩”等模糊指令自动添加大量转场、字幕动画或音效。可保存具体风格约束，如字幕规范、音乐强度和剪辑密度；用户每次修正都能更新本项目约束。

### Agent 与版本

| 编号 | 级别 | 需求与验收 |
| --- | --- | --- |
| R18 | P0 | 自然语言任务、选区引用、范围约束和项目风格；任务开始前展示解析后的范围 |
| R19 | P0 | 进度、追加意见、中断和恢复；中断后不能继续静默提交旧计划 |
| R20 | P0 | 人工修改保护、属性锁定和冲突检查；所有锁定用例通过后才可开放持续自动编辑 |
| R21 | P0 | 编辑组撤销重做、命名快照、创建独立版本、前后对比；对比保留准确的版本身份 |
| R22 | P0 | 修改摘要显示改了什么、位置、时长变化和预览入口；可展开查看来源与判断依据 |
| R23 | P0 | 模型连接错误、额度耗尽和网络中断可恢复；失败不损坏已提交工程 |
| R24 | P1 | 多种 Agent 底座适配、对外 MCP 或 CLI 接口、可复用工作流与批量任务 |
| R25 | P2 | 多人协作、审片批注流转、版本继承与跨版本批量应用修改 |

首版只需要一种稳定的 Agent 底座和可配置模型连接。模型思考过程不作为剪辑结果的证明，应以实际工程变化和预览为依据。

### 检查与交付

| 编号 | 级别 | 需求与验收 |
| --- | --- | --- |
| R26 | P0 | 导出前检查缺失素材、待补画面、时间线空洞、字幕溢出、音频峰值和不同步风险；区分确定错误与待人工判断项 |
| R27 | P0 | 对受影响区间生成可播放预览；用户检查切口、节奏、配音与闪帧，不能只依赖静帧检查 |
| R28 | P0 | 本地 MP4 导出、SRT 导出、队列、进度、取消和重试；导出使用固定版本快照 |
| R29 | P0 | 导出完成记录实际文件位置、时长、分辨率和对应版本；工程随后变化不改变已完成文件的身份 |
| R30 | P1 | 工程打包、收集素材、第三方时间线格式导出；逐格式说明支持范围与降级方式 |
| R31 | P1 | 签名安装、更新、迁移和诊断；更新失败可恢复，错误报告默认不携带原始媒体 |
| R32 | P2 | 专业色彩管理、高级音频、多机位、HDR 和更复杂的工程互通 |

## 费用与数据控制

### 执行权限

普通、可撤销的工程编辑在用户提出任务后持续执行，不逐步打断确认。用户对素材上传和付费服务的授权按项目保存，不能每次调用重复询问。

首次需要发送媒体时，说明发送的是原视频、音频、抽帧还是转录，以及接收服务。后续在既有授权范围内继续；更换供应商、扩大上传范围或超过费用上限时，再请求对应决定。

源文件删除、覆盖已有成片和对外发布不属于普通剪辑权限。首版不支持自动对外发布；导出默认创建新文件。

### 成本展示

费用分为内容分析、Agent 推理、素材生成和远程存储或渲染。任务开始时显示可估算部分及未知项；结束时显示供应商返回的实际用量，无法确认的费用标记为待同步。

单项目支持费用上限。达到上限时停止新的付费请求，保留手动编辑和本地导出。重试先核对已有任务状态，避免对同一次生成重复扣费。

总使用成本按“分析用量 × 单价＋推理用量 × 单价＋生成时长或数量 × 单价 × 尝试次数＋远程资源费用”计算。本地处理仍有运行时间、内存和磁盘成本。

### 本地与云端

工程和原素材默认由用户在本地管理。云端模型只获取完成任务所需且已授权的内容；本地保存不等于所有推理都离线。

模型密钥存入系统安全凭据存储，不进入工程文件和导出包。清理缓存前显示占用和影响，原素材、工程版本和生成成果分别管理。用户主动提交诊断时可以检查所附内容。

## 异常状态与恢复

| 情况 | 用户看到的状态 | 必须保留的能力 |
| --- | --- | --- |
| 分析尚未完成 | 哪些素材可用、哪些仍在处理 | 预览、手动编辑、已完成素材的 Agent 操作 |
| 模型请求失败 | 原因、已完成步骤、重试入口 | 已提交编辑、手动操作与本地导出 |
| 人工修改与 Agent 冲突 | 冲突位置及重新计算状态 | 人工结果优先保留 |
| 用户停止任务 | 已完成结果与尚未完成部分 | 撤销、继续编辑、按检查点恢复 |
| 源素材移动 | 离线素材列表与重新定位入口 | 文稿、分镜、轨道结构及其他在线素材 |
| 磁盘空间不足或保存失败 | 明确的未保存状态 | 停止新的自动写入，允许选择新存储位置 |
| 生成结果已返回但任务被停止 | 素材库中的未采用候选 | 用户可自行插入，不自动覆盖时间线 |
| 应用异常退出 | 恢复到最后一个持久化编辑组 | 不丢失已显示为保存成功的修改 |
| 导出过程中继续剪辑 | 标明导出所用版本及当前版本 | 当前工作继续，导出结果保持确定 |
| 导出失败 | 可定位的阶段、错误与重试入口 | 工程和原素材不变，不把残缺文件标为成功 |

## 质量目标与验证方法

以下是拟定验收目标，需在技术验证阶段校准；未实测的数据不作为已达到的性能承诺。

### 首版基准环境

参考设备为 Apple M2、16 GB 内存、内置 SSD；最低 macOS 版本待验证。测试工程包含总长 30 至 60 分钟的源素材，输出 1 至 5 分钟；最多同时播放三层视频或图片及四路音频，带字幕和基础淡入淡出。此配置定义性能测试范围，不是永久轨道数量限制。

首版基线输入为 MP4 或 MOV 中的 H.264 与 AAC，以及 PNG、JPEG、WAV、MP3；输出为 1080p SDR H.264 与 AAC，支持 16:9、9:16、1:1，项目帧率为 24、25、30 fps。HEVC、HDR、4K 和其他组合先做兼容验证，再决定纳入阶段；不能静默误读色彩或帧率。可变帧率输入需要规范化处理并保持音画同步。

### 工程与性能指标

| 项目 | 拟定目标及测法 |
| --- | --- |
| 操作反馈 | 本地按钮、选区与拖动的可见反馈 P95 不超过 100 ms；不含模型等待 |
| 预览定位 | 代理就绪后，随机定位至目标画面 P95 不超过 500 ms |
| 连续播放 | 基准工程连续播放 60 秒，无持续卡顿；分别记录丢帧与音频中断 |
| 停止反馈 | 点击停止后 200 ms 内更新状态；停止请求被接受后禁止新编辑组提交 |
| 时间准确性 | 编辑边界与目标相差不超过一个项目帧；正常速度影音素材相对源内容无超过一帧的新增偏移 |
| 保存恢复 | 已确认持久化的编辑组在强制退出恢复用例中零丢失；未完成组不得部分恢复 |
| 预览与导出 | 同一版本的时长、构图、字幕、混音符合一致设置；抽样检查切口及转场 |
| 人工保护 | 锁定、范围约束、并发修改回归用例全部通过，不允许静默覆盖 |
| 费用保护 | 同一付费任务重试不重复提交；达到上限后不再发起新的付费请求 |

模型端耗时单独记录分析等待、首个可预览结果时间和总任务时间。供应商拥堵不能伪装为本地编辑无响应。

### 内容质量

口播版本必须保留指定论点、否定词和限定条件；删除停顿需保留表达和情绪节奏。短片版本需要检查旁白与画面对应、镜头衔接和信息揭示顺序。所有类型都需要人工播放检查字幕可读性、音量、切口、卡顿和闪帧。

质量检查结果可标记“通过”“需要人工判断”“阻塞交付”。检测到全黑画面或静音不自动认定错误，也可能是用户刻意保留的内容。

## 验收项目与产品指标

### 三个完整验收任务

| 任务 | 输入与操作 | 通过条件 |
| --- | --- | --- |
| A 访谈初剪 | 30 分钟中文访谈剪成约两分钟；恢复一句话并锁定结尾；再要求缩短中段 | 指定内容保留、锁定生效、字幕同步、可以回退并导出 |
| B AI 短片组装 | 三场戏剧本、配音和 10 至 20 个已有镜头组装约一分钟短片；人工换镜头后继续交给 Agent | 分镜与来源对应、候选保留、人工选择未被旧计划覆盖、缺失项明确 |
| C 多版本修改 | 一个约三分钟工程；只修改第三段字幕和节奏，再派生竖屏版 | 任务范围外内容未被意外改变、两版本独立、构图可修正、导出身份明确 |

每类至少准备三套不同素材，共九个真实验收工程。以上工程各执行一次中断恢复、一次人工冲突、一次撤销以及一次完整导出；再加入缺失素材和网络失败用例。

### 指标定义

北极星指标为“完成并被创作者接受的可编辑成片数”。只有用户确认可用或明确选择最终版，且工程可重新打开与导出，才计为完成；单纯渲染成功不计入创作质量完成。

| 指标 | 统计方式与初期目标 |
| --- | --- |
| 具体指令成功率 | 至少 50 条有明确预期的编辑任务，首次执行正确且不违反约束的比例目标为 90% 以上 |
| 三类流程覆盖 | 九个验收工程全部能够完成导入至交付流程 |
| 人工返工 | 同素材、同交付要求与纯手动基线比较；稳定使用后主动操作时间中位数下降目标为 50% |
| 初剪接受度 | 由创作者对结构、节奏、字幕、画面与声音分别评分，记录主要修改原因 |
| 工程可靠性 | 发布门槛内的恢复、锁定和范围保护用例必须全部通过 |
| 成本效率 | 分场景记录每个被接受成片的分析、推理和生成费用，不能只记录单次请求费用 |

开放式审美任务不与精确剪辑指令混为一个成功率。公开测试前确定固定评测集和评分规则，发布后在取得用户同意的前提下收集产品事件；默认不采集原始媒体与完整转录。

## 实现约束与候选方案

本节规定需要保障的产品能力，具体语言、界面框架和存储设计由后续技术设计确定。

1. 人工与 Agent 共用编辑接口。修改前检查版本、选择范围、锁定和素材有效性，修改后形成可撤销编辑组。
2. 工程状态独立于聊天记录保存。对话删除、模型切换或 Agent 重启不能使剪辑工程丢失。
3. 分析、生成、导出具有独立任务身份和恢复状态，不能因对话上下文被压缩而遗忘未完成任务。
4. 时间线保留源素材和入出点；生成内容与外部素材都可追踪来源。时间计算须支持帧级精度。
5. 预览和导出使用相同的工程含义；代理与原素材切换不得改变剪辑边界。
6. 工程格式需要版本与迁移策略。媒体文件可重新定位，缓存可重建。

Pi 提供 SDK、会话与工具扩展，以及追加指令和中断机制，可作为首轮集成候选。[Pi SDK](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/sdk.md) DeepSeek Harness 采用可替换的插件架构，可作为扩展能力的对照候选；其开发者预览状态和不兼容变更风险需纳入维护评估。[DSH 架构](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md) [DSH 状态](https://github.com/deepseek-ai/deepseek-harness)

媒体层优先验证本地播放与合成能力。AVFoundation 的自定义视频合成接口可用于播放与导出，但其在本产品目标轨道、字幕和效果下的性能需要实测。[Apple AVVideoCompositing](https://developer.apple.com/documentation/avfoundation/avvideocompositing)

首轮技术验证比较：工具调用可靠性、打断延迟、恢复完整性、嵌入成本、依赖升级成本与媒体预览性能。技术选择不以聊天演示效果作为唯一依据。

## 研发阶段与成本估算

按两名熟悉桌面与音视频的工程师、AI 辅助开发、采用现有模型和媒体基础设施估算。下表为累计时间量级，受媒体引擎选型和实际工程兼容性影响；在第一阶段结束后重新估算。

| 阶段 | 累计时间估算 | 退出条件 |
| --- | --- | --- |
| 技术和交互验证 | 2 至 4 周 | 在真实素材上完成导入、预览、Agent 修改、人工接管、撤销和导出；验证冲突与停止规则 |
| 自用 Alpha | 8 至 14 周 | P0 完整，三类验收项目可交付，恢复与人工保护通过 |
| 个人创作者公开测试 | 4 至 6 个月 | 在 Alpha 基础上完成必要安装更新、兼容性和稳定性工作；提供费用控制与可用诊断 |
| 专业化扩展 | 根据使用数据排期 | 按付费用户需要推进关键帧、工程交接、多机位与高级色彩音频 |

两人全职对应的阶段投入量级分别约为 1 至 2、4 至 7、8 至 12 人月，均按累计量计算，不能逐行相加。现金预算应按实际人力成本、开发设备、签名分发、测试素材与 API 用量另算。

共同底座主要投入在媒体引擎、工程恢复、编辑界面和人与 Agent 协作。访谈增加转录与语义剪辑；短片增加分镜、候选与叙事关系；多版本增加构图和版本隔离。生成完整镜头、支持更多外部工程格式，会引入额外成本。

首轮不设未经实测的固定“每条成片成本”。按三个验收场景分别记录单次分析、每轮修改、每个采用镜头和最终成片的费用；重点控制重复分析、无效重试和低采用率的生成素材。

## 主要风险与应对

| 风险 | 产品应对及验证 |
| --- | --- |
| 连续修改后工程越来越不可控 | 统一编辑接口、范围与锁定、版本快照；用连续十轮修改和混合人工操作验证 |
| Agent 会操作但剪辑判断不佳 | 建立场景任务与审片标准，保存项目风格约束，允许低成本局部重做 |
| 预览流畅但导出不一致 | 同一工程含义与固定导出版本；检查构图、转场、字幕及音频 |
| AI 镜头生成费用失控 | 将组装与生成分开，项目预算、候选采用记录、任务去重 |
| 中文转录和人名识别错误 | 允许校正文稿与术语，保留音频定位，避免误改原声 |
| 成片再编辑被误解为恢复源工程 | 导入时展示可编辑层级，对不可分离内容给出具体限制 |
| 模型或 Agent 框架更新破坏行为 | 固定验证版本、适配边界和回归集，通过验证后升级 |
| 支持范围扩张拖慢首版 | 以九个真实工程为范围锚点，新增功能必须对应明确工作流和验收 |
