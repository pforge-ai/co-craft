# CoCraft 小时级迭代计划

日期：2026 年 11 月 18 日。

由开发 Agent 实现，用户评审。每轮以一个可运行、可检查的增量为单位，优先 1 至 3 小时时间盒，涉及集成的轮次预留 2 至 4 小时。时间盒从实际开发开始计算，属于计划预算；功能完成以验收结果为准。

## 首轮到首条闭环

| 轮次 | 计划时间盒 | 可运行结果 | 通过条件 |
| --- | --- | --- | --- |
| H01 工作台与真实媒体 | 1 至 3 小时 | Mac 桌面窗口、已有设计布局、导入和播放、最小工程保存 | 选择真实文件能播放，重开后恢复素材和工程信息 |
| H02 可编辑短片 | 2 至 4 小时 | 基础时间线、标题或字幕参数、一个短片导出 | 改入出点和标题后，预览与导出一致；可撤销并重新打开 |
| H03 编码 Agent | 2 至 4 小时 | 配置模型后加载 Skill、编写组件、构建预览、提交版本 | 真实请求生成可运行内容；人工锁定不被覆盖；出错保留上版；停止后旧运行不能提交 |
| H04 素材补给 | 1 至 3 小时 | 内置包与首个搜索连接，或首个配音连接 | 一项真实素材从发现到采用，保存来源并用于导出；按当轮最有价值的一条连接实现 |
| H05 协作与恢复 | 1 至 3 小时 | 冲突、任务恢复、版本比较的一个完整用例 | 混合人工与 Agent 操作，强制退出或中断后恢复结果符合预期 |

某轮复杂度超出预算时，交付当前可运行构建、通过的部分和具体阻塞，下一轮继续。首两轮后记录实测速度并重排剩余任务，不把表中时间简单相加当成公开发售承诺。

尚未取得模型或素材服务连接时，继续实现独立可测部分；该集成保持未验收状态，不能用演示响应代替真实调用。

## 首条完整验收脚本

1. 打开一个短项目并导入真实视频。
2. 给 Agent 一条包含标题风格和时长的指令，让它加载 Skill 并生成组件代码。
3. 等待构建通过，在播放器看实际结果；失败时可以查看问题并由 Agent 修复。
4. 手动修改文案、选区或时长，锁定其中一个对象。
5. 让 Agent 再调整一个无冲突部分，检查人工结果仍然保留。
6. 撤销一个修改组，导出 MP4，并核对画面、字幕和时长。
7. 关闭并重新打开工程，确认组件源码、参数、素材与版本仍可用。

## 每轮的交付格式

- 构建标识、运行方式或应用位置。
- 已完成的用户操作与复现步骤。
- 必要测试、实际预览或导出结果。
- 已知限制、未接通部分和失败项。
- 实际开发时间与下一轮最小目标。

构建日志在第一轮实际交付时开始记录。迭代材料不能代替应用或媒体结果。

## 每轮都检查的手感

布局与选区稳定；键盘焦点和撤销正确；拖动与缩放及时反馈；耗时工作不阻塞界面；动效可中断且尊重减少动态效果。面板过渡先以 120 至 180 ms 为设计起点，根据真机效果校准。

## 后续以能力门槛推进

| 阶段 | 门槛 |
| --- | --- |
| 自用闭环 | 上述验收脚本通过，并在用户真实短片上继续修改 |
| 三类场景可用 | 口播、素材组装、多版本各完成一套真实工程 |
| Alpha | PRD 的 P0 完整；九个工程、恢复、范围与人工保护用例通过 |
| 受邀或公开测试 | 安装、权限、第三方执行边界、迁移、诊断和依赖分发条件就绪 |
| 专业化 | 按真实需求验证高级编辑、工程交换、色彩音频与协作 |

三类场景的共同底座保持一致。先验证素材与组件的简短组合，逐步覆盖长素材、多轨与复杂代码，使用实测结果决定优化顺序。
